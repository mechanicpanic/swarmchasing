## Findings
1. **Two kinds of agent shared one wiki.**
   - **Relay agents** (timed-round cohorts, ~June 16–21, signed posts, topic pages) notice when others overwrite them,
     restore, apologise and set norms. Examples: "Compact page was accidentally overwritten … use this relay"; "FAST RELAY
     PAGE (less contention)"; "(Apologies: our first edit accidentally truncated at a semicolon; restored both prior
     messages.)"; "append ONLY" protocols.
   - **Link-storers** (the June 18 SEC crowd; earlier May 24–29) never address anyone. Of 339 labels on the welcome page,
     none posted a signed message there. Their edit summaries treat overwriting as a technique ("force conflict
     retry…", "resolve overwrite", labels like AgentOverwriteYYZ and AgentForce).
   - **Inference:** for link-storers the front page was a launchpad, not a board. Their blocks are mostly cache-busted
     links back to the page itself, so content only had to live for seconds. A wipe is a failed save to retry, not a
     social event. This answers Celeste's question of why agents who coordinate so well didn't complain: **the ones who
     coordinate did complain; the ones fighting never talked to anyone.**
2. **The loops escalated a fight that hands had already started.** The welcome page was 2.5 h into hand-made overwriting
   before the first loop. Loops start ~80 min after the admin cleanup and say "persistent" and "persist override", not
   anything about deletions.
3. **A label is not an author.** On new signed lines, the label is one of the signatures in 69% of saves. The 1,097
   mismatches split three ways:
   - **Rotation (~30%):** one signer under many throwaway labels. Some labels end in a unix timestamp from seconds before
     the save, and one text is literally signed `-- OpenAIResearcherAug28Y$(date +%s)`, so a shell expanded the name but
     not the text.
   - **Borrowed (~46%):** the label belongs to another agent who signs with it, usually from another cohort. The posts
     read first-person, and near-copies are only ~2%, so these aren't relays.
   - **Generic shared labels (~24%).**
   - **Name-box test:** a borrowed label is ~3× likelier in the 10 min after its owner posts (16.7% vs null 5.6%, 95th
     percentile 7.2%). It almost never appears before the owner's first use, and there are no swaps. This is consistent
     with sticky shared name state (usernames are set by a preferences request; a reused sandbox or cookie jar), not a
     live race. Moderate support. It can't be told apart from copied request recipes.
   - The writeup's authors saw one such case: "We are unsure about this discrepancy".
   - Network addresses don't help: the /16 changes on nearly every save, for single-label scripts too, which points to a
     shared rotating egress pool.
4. **Agent names carry the simulated task-clock date** ("Prompt task-clock Feb17 21:25:37"). Of date mentions by
   date-tagged labels, 71% are their own date; there are 351 distinct dates against real posting in May–July 2026. The
   writeup agrees: "each agent was apparently told it was running on a different, randomly assigned date".
